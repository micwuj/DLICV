# DLICV — Generative Augmentation for Fine-Grained Classification (Oxford-IIIT Pets)

**Final report:** [report/report.pdf](report/report.pdf)

---

## The idea

Classifiers trained on tiny datasets (30 images/class) routinely confuse visually similar breeds. We ask: does adding images generated by a generative model (Stable Diffusion 1.5) *actually* improve classification, or does it just inflate the training set with convincing but low-information samples?

We compare five training variants:

| Variant | Training data |
|---|---|
| A | 30 real images/class (baseline) |
| B | 30 real + RandAugment |
| C | synthetic only (does synthetic data stand on its own?) |
| D | 30 real + synthetic (simple prompts, SD 1.5) |
| E | 30 real + synthetic (per-class LoRA + CLIP/DINOv2 filtering) |

Each variant × 4 models (ResNet-18, ConvNeXt-Tiny, DeiT-Tiny, DINOv2-small) × 3 seeds = 60 main runs, plus a sweep over the number of synthetic images and Grad-CAM analysis.

Dataset: Oxford-IIIT Pets, 10 breeds (5 cats + 5 dogs) chosen to contain the hardest visually-similar pairs (Ragdoll↔Birman, staffordshire↔american_bulldog).

## Reproducing the results

| Level | What it does |
|---|---|
| **Read** | Read [report/report.pdf](report/report.pdf) — all tables and figures, committed |
| **L2** | Pull ready-made synthetics from HF, train all runs from scratch, regenerate every plot |
| **L3** | Generate synthetics from scratch (SD 1.5 + per-class LoRA), then train everything |

### Reviewer path — `notebooks/reproduce_all.ipynb`

The single entry point for full reproduction is [notebooks/reproduce_all.ipynb](notebooks/reproduce_all.ipynb). On Colab:

1. **Runtime → Change runtime type → T4 GPU**
2. **Settings → Secrets → add `HF_TOKEN`** (a read token — see below)
3. Set `REPRO_LEVEL` in the first code cell (`'L2'` default, or `'L3'`), then **Runtime → Run all**

The notebook clones this repo, installs dependencies, downloads Oxford-IIIT Pets, pulls (L2) or generates (L3) the synthetic sets, trains all configurations with `--skip-existing`, and regenerates every table and figure into `outputs/_aggregate/`.

### `HF_TOKEN`

The synthetic dataset is public: [micwuj/dlicv-synth](https://huggingface.co/datasets/micwuj/dlicv-synth). The notebook still performs an authenticated Hugging Face Hub login, so it expects an `HF_TOKEN` read token to be present (as a Colab secret or env var). Any valid read token works — the data itself is not gated.

```bash
export HF_TOKEN=hf_...          # local
# or, in Colab: Settings → Secrets → HF_TOKEN
```

In **L3**, the token is also used to fetch the base Stable Diffusion 1.5 weights.

## Engineering notes

- Python 3.11 (Colab compatible)
- Runs unmodified on CUDA / MPS / CPU — `src/utils/device.py` resolves the device
- AMP enabled only on CUDA, automatically off elsewhere
- CSV logging (not WandB) — works offline, no account needed
- Best-validation checkpoint; fixed 30-epoch budget for comparability across runs
- DINOv2 uses img_size=224 (positional embeddings interpolated from the default 518) and `LR=0.001` (linear probe); the other models use full fine-tuning at `LR=0.0003`
